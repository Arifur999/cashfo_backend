Prompt 9: System/Technical Management

Adds BackupRecord, FeatureFlag, ErrorLog, and ApiRateLimitLog models
(everything simulated/manual-trigger rather than wired to real
infrastructure, per the prompt's own instruction -- see the module-level
comment in system.module.ts for what's a stand-in vs. production-ready).

Backups: trigger simulates a job completing a few seconds later via
setTimeout, status-summary computes days-since-last-backup and a 30-day
success rate. Feature flags: toggle/rollout/target-plans with a public
evaluate endpoint using a deterministic SHA-256 hash of (key, user) for
consistent, roughly-uniform rollout bucketing. Error logs: manual report
endpoint plus a global exception filter (extends BaseExceptionFilter,
delegates to super.catch() so no existing response shape changes) that
logs genuine 5xx failures automatically. Rate limits: list + summary
views over the (currently seed-only) ApiRateLimitLog table.

Every route is SUPER_ADMIN only except feature-flags' evaluate (public,
for the future end-user app) and errors' report (any authenticated
admin, so crashes in non-SUPER sessions still get logged) -- same
per-route-guard pattern as Prompt 7's analytics/track endpoint.
